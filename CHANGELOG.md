# Changelog

Formato baseado em [Keep a Changelog](https://keepachangelog.com/pt-BR/1.1.0/) e [SemVer](https://semver.org/lang/pt-BR/).

## [Não lançado]

### Corrigido
- Aviso "começa hoje" contava qualquer colaborador ativo da equipe; agora só admissões do dia.
- Logs verbosos do Azure SDK e do httpx (e métricas ao vivo) desligados: menos custo e nenhuma URL do Graph nos logs.
- Admissões mostram "Desligado depois" quando a conta teve desligamento.
- Ativação no D0 falhava com 403: o nível `ciclo-de-vida` agora concede `User.EnableDisableAccount.All`.
- Listagem de solicitações com ordem estável quando duas têm o mesmo horário de criação.
- Mensagem clara quando o Graph recusa o TAP; link de primeiro acesso para `mysignins.microsoft.com/security-info`.

### Adicionado
- Sprint 11: novo visual inspirado no Fluent 2 — menu lateral com ícones (recolhível no desktop, gaveta no celular), topo com avatar e menu da conta (Popover API), tema claro/escuro automático com botão (preferência salva só no navegador, sem piscar), página inicial com atalhos, cartões, tabelas, formulários, selos de status, linha do tempo e abas redesenhados; CSS moderno sem build nem dependências (`@layer`, aninhamento, `light-dark()`, `color-mix()`, `:has()`, view transitions, `prefers-reduced-motion`); ícones SVG próprios; acessibilidade (pular para o conteúdo, foco visível, `aria-current`); tudo compatível com a CSP (nenhum estilo ou script inline).
- Sprint 10: workflow `Deploy` (CI reutilizável → publicação automática no lab a cada push na `main`; produção manual com aprovação e somente da `main`; nova tentativa em 502 do F1; conferência do `/health`), login no Azure por OIDC sem segredos, script `New-GitHubDeployIdentity.ps1` (App Registration sem segredo, credencial federada por ambiente, papel Website Contributor somente no Web App, ambiente e variáveis no GitHub), testes que garantem ausência de segredos e o escopo mínimo.
- Sprint 9: trilha de auditoria automática e somente de acréscimo (transições, etapas, TAP sem o código, perfis, agendador, exportações; sem dados pessoais do colaborador), tela de auditoria com filtros e exportação CSV protegida contra injeção de fórmulas, painel do Administrador (pendências, falhas, próximos 7 dias, licenças, última execução do agendador), LGPD: retenção configurável (`LGPD_RETENTION_DAYS`) com anonimização automática e manual, aviso de privacidade (`PRIVACY_CONTACT`); variáveis `OFFBOARDING_BLOCK_HOUR`, `LGPD_RETENTION_DAYS` e `PRIVACY_CONTACT` passam pela infraestrutura.
- Sprint 8: desligamento com aprovação — pedido do RH (colaborador pela busca no diretório, último dia, opção de bloqueio imediato), revisão com os acessos atuais, segregação de funções (ninguém pede nem aprova o próprio desligamento), revalidação no tenant, bloqueio agendado (`OFFBOARDING_BLOCK_HOUR`) executado pelo agendador: bloquear conta, revogar sessões, registrar `employeeLeaveDateTime`, remover dos grupos (inclusive licença) e, com `LICENSE_MODE=direct`, das licenças diretas; ações manuais registradas (grupos dinâmicos, listas de distribuição, grupos com funções, subordinados, funções administrativas); cancelamento do desligamento agendado; status `desligada`; a conta nunca é excluída; nível de permissão `desligamento` (`User.RevokeSessions.All`); listas mostram tipo e data efetiva.
- Sprint 7: motor de ciclo de vida nativo (licença no D-1 por grupo ou SKU direto, com verificação de unidades; ativação no D0; estados `licenciada`/`ativa`; novas tentativas automáticas), agendador Logic App de hora em hora chamando `/interno/ciclo-de-vida` com Managed Identity e App Role de aplicação `Provisionamento.Agendador`, botão "Executar ciclo de vida agora", área **Minha equipe** onde o gestor gera o Temporary Access Pass (uso único, validade limitada pela política, exibido uma vez e nunca armazenado), nível de permissão `ciclo-de-vida`.
- Sprint 6: `UserProvisioningService` cria a conta aprovada no Entra ID (desativada, sem licença, senha aleatória descartada, `forceChangePasswordNextSignIn`), define gestor, matrícula, tipo, data de admissão e grupos de acesso (revalidados no tenant); etapas registradas individualmente, falha parcial com reprocessamento pelo Administrador (idempotente, reaproveita usuário de tentativa anterior, nunca exclui); `DRY_RUN` simula tudo; limite diário `PROVISIONING_DAILY_LIMIT`; escrita isolada em `MsGraphWriter` (sem repetição de POST ambíguo); nível de permissão `criacao` no `Set-GraphPermissions.ps1`; busca de gestor com mensagens de erro claras.
- Sprint 5: solicitações gravadas com Request ID `REQ-AAAAMMDD-NNNN`, máquina de estados (enviada → aprovada/rejeitada/cancelada) com histórico, fila de aprovação, segregação de funções (quem solicita não aprova), comentário obrigatório na rejeição, revalidação no tenant ao aprovar, reserva de UPN/matrícula entre solicitações em andamento, idempotência e proteção contra duplo clique, concorrência otimista (ETag no Azure Table), avisos na página inicial e visão de todas as solicitações para o Administrador. Testes de contrato de armazenamento também no Azurite.
- Sprint 4: formulário de novo colaborador (campos com limites do Graph, busca de gestor), motor de nomes/UPN configurável (acentos, partículas, colisões `joao.silva` → `joao.silva2` verificadas em UPN, e-mail, alias e proxyAddresses de usuários e grupos), checagem de matrícula duplicada, tela "Revisar criação do usuário" com linha do tempo D-1/D0 e envio **simulado** (nada é gravado nem criado).
- Sprint 3: `GraphService` somente leitura (Managed Identity, paginação, retry com `Retry-After`, bloqueio de escrita); página de capacidades do tenant (licenças, P1/P2/Governance, TAP, domínios, grupos); perfis de onboarding (grupos de acesso + licença) validados contra o tenant no backend; APIs de busca de gestores e verificação de endereço; proteção CSRF; script `Set-GraphPermissions.ps1`; modo `GRAPH_BACKEND=fake`.
- Sprint 2: login com Microsoft Entra ID via App Service Authentication sem Client Secret (fluxo de ID token por padrão; Managed Identity como credencial federada opcional); App Roles Solicitante/Aprovador/Administrador atribuídos a grupos; validação de tenant, audiência e papéis no backend; modo `AUTH_MODE=dev` para desenvolvimento local; script `New-EntraApplication.ps1`.
- Sprint 1: estrutura do projeto, FastAPI com `/health` e `/health/ready`, cabeçalhos de segurança, armazenamento SQLite/Azure Table, infraestrutura Bicep (App Service, Managed Identity, Storage, Application Insights) e scripts de implantação.
